# 微服务重启原因分析（找日志）

## 症状
- 表现：微服务 Pod 重启 / 被杀，需要定位原因
- 影响面初判：该服务可用性

## 排查路径

### 1. 宿主机层：确认是否内核 OOM Kill
```bash
# 登录执行机宿主机
grep -i oom /var/log/kubelet*    # kubelet 日志中的 pod 事件
dmesg -T | grep -i -E "oom|kill"
```
- 命中 OOM Kill → 转第 3 步内存分析
