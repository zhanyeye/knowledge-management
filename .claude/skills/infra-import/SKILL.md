# infra-import — 导入整理

把原始材料（文档/表格/聊天记录/口述）变成结构化知识草稿。

## 流程

### 1. 理解材料，逐条分类

一条「场景」一个文件（不要把 20 个场景塞进一个大文档）。按 AGENTS.md 判定表分类：

| 材料特征 | kind |
|---|---|
| 描述一个对象的事实（实例/集群/域名/证书/平台） | registry（YAML） |
| 描述一个动作怎么做（申请/配置/扩容/发版） | runbook |
| 描述一个症状怎么查 | playbook |
| 描述一个选型/设计理由 | adr |
| 短问答 | faq |
| 链路/拓扑 | architecture |
| 一次真实故障的完整复盘 | case |

材料是混合体时拆成多条，互相用 `related` 链接。

### 2. 生成草稿

```bash
python scripts/infra.py new <kind> <中文文件名> --title "<中文标题>" --tags "<逗号分隔中文标签>"
```

然后填充内容，规则：

- **原始材料里的步骤/参数原样保留**，填进模板对应章节（操作步骤/排查路径）
- 材料里没有的信息（前置条件/验证/回滚/负责人）**写 `TODO`，禁止编造**；不确定的命令标 `待确认`
- runbook/playbook 评估 risk：只读诊断=low；一般变更=medium；生产高危（证书/批量/删数据/核心发版）=high
- 涉及具体资源对象：同步 `new registry <名称>` 补台账，并在两边的 knowledge/related 里互相链接

### 3. 校验与交付

```bash
python scripts/infra.py lint    # 错误必须清零（TODO 不算错误）
python scripts/infra.py index   # 刷新索引（草稿会带草稿箱标记出现在 INDEX）
```

向用户报告清单：每条草稿的「文件 → 建议转正路径 → 遗留 TODO」（更新 草稿箱/MANIFEST.md），等待 review。

### 4. 转正（人工动作）

用户确认后：`git mv 草稿箱/<文件> <目标分区>/ && python scripts/infra.py index`。
用户口头确认即视为同意转正时，列出将要执行的 git mv 命令再执行。

## 批量导入（如痛点场景表）

表格逐行处理：一行=一个场景=一个文件；「问题/场景」列做标题与 tags 来源，「当前步骤」列填进排查路径/操作步骤。量大时分批交付（每批 ≤10 条），避免用户一次 review 过载。
