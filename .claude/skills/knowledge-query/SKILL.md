# 团队 wiki 按需消费协议

## 触发时机

- 排障任务（现象 → 先查 踩坑/手册）
- 开发/评审任务（先查 规范/决策）
- 执行运维操作（先读对应 手册，并遵守 ops-runbook-guard）

## 检索流程（不得跳级、不得遍历）

1. **总目录**：读 `catalog.md` → 定位目标分区
2. **目录索引**：读该目录 `catalog.md`（一行一条）→ 挑出候选
3. **条目全文**：只读预算内条目

## 查询预算（按任务类型，配置在 .wiki/config.json → query_budgets）

| 任务类型 | 目录索引 | 全文条数 | 优先类型 |
|---|---|---|---|
| troubleshoot | ≤2 | ≤3 | 踩坑 → 手册 → 现状 |
| implement | ≤2 | ≤4 | 规范 → 踩坑 → 决策 |
| ops_execute | ≤1 | 1（完整读） | 手册 |
| default | ≤2 | ≤5 | — |

## 引用闭环（消费即记录）

命中并使用了知识后：`python .wiki/scripts/wiki.py reference <编号> --in "<任务上下文>"`。
引用计数决定知识是否衰减——不记录引用的知识会被 decay 降级归档。

## 技巧

- `python .wiki/scripts/wiki.py search <关键词> --limit 3` 跨目录定位（支持中文/英文/tag/编号）
- `[draft]` 未验证，回答时声明置信度
- "现状"类条目先核对正文里的最后刷新时间
