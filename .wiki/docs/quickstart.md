# 用户上手指南（先会用，再看架构）

> 你不需要懂编号、成熟度这些概念——那是引擎自动管的。
> 打开本仓库的 Claude Code（或其他 Agent CLI），记住下面两个命令就够了。

## 只需记住的两个命令

| 你想干什么 | 输入 |
|---|---|
| **查**：排障、找规范、找运维手册、找历史决策 | `/wiki <用一句话说你的问题>` |
| **存**：处理完故障/做完选型，把经验留下来 | `/wiki-save` |

## 空库冷启动（团队第一次部署时）

刚部署时知识库是空的，`/wiki` 查不到东西很正常。让维护者先跑一次：

```
/wiki-import <旧 wiki 或文档所在目录>
```

Agent 会把旧文档（ADR/runbook/FAQ/资产清单…）按内容归类导入，缺失的步骤自动生成
"待专家确认"清单——正好拿去和专家逐条核对补全。导入后 `/wiki` 就有料了。

## 场景走查

### 场景 1：我遇到问题了（最高频）

```
你：/wiki rancher UI 登录不上，页面 502
```

Agent 自己查索引 → 找到相关条目（踩坑/手册）→ 给你排查步骤，标注来源编号和置信度（`[draft]` 未验证之类）。
你照着做，**完事**（引用已自动记录）。

### 场景 2：我处理完一个故障，想留下来

```
你：/wiki-save
```

Agent 回顾会话 → 起草 1~2 条知识候选放进 `pending/` 暂存区 → 列给你看。
你扫一眼、改掉不对的命令，确认后 Agent 执行 promote 转正（1 分钟）。

### 场景 3：同事说"这条知识你帮忙验证下"

```
你：/wiki-verify K8-003 --by 你的名字 --project 项目名
```

这条知识可信度升一级（draft→verified）。**可信度全靠真实用过的人背书**，这一步是 wiki 不腐烂的关键。

### 场景 4：维护者才用（普通成员可忽略）

| 时机 | 命令 |
|---|---|
| 把旧 wiki 批量导入 | `/wiki-import <目录>` |
| 定期清理膨胀/过时 | `/wiki-clean --fix` |

## 不用 Claude Code 行不行？

行，本质就是个 git 仓库 + markdown：

```bash
python .wiki/scripts/wiki.py search "证书"            # 检索
python .wiki/scripts/wiki.py new 踩坑 "标题" --layer 通用 --owner 你
# 或者直接照 examples/example-entry.md 的格式写个 md，git 提交
```

## 自动运转的部分（你不用管）

| 机制 | 谁在做 |
|---|---|
| 条目编号、目录索引 | wiki.py new/index 自动 |
| 可信度升降 | /wiki-verify 驱动；长期没人用的自动降级、归档（可恢复） |
| 格式/安全检查 | git 提交时钩子自动 lint |
| 高危操作保护 | Agent 执行手册时自动分级（high 风险必须你逐步确认） |

## 常见疑问

- **我的知识该放哪？** 直接问 Agent；或一句话判断：只对一个项目有用→`项目/<项目名>/`；跨项目通用→`通用/`；基础设施→`基础设施/<子域>/`。
- **我不是专家，写错了怎么办？** 新知识一律 draft 起步，被人实际用过才升级；Agent 不确定的地方会写"待专家确认"而不是编造。
- **某条知识可不可信？** 看目录索引标记：`[draft]` 未验证、`[verified]` 一人验证、`[proven]` 多人多项目验证。
